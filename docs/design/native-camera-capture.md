# On-demand native camera source

The Linux camera implementation lives in `porthub-media-helper/src/linux_video.rs` and `linux_video_native.rs`. It is wired in the unpublished native-media worktree through the explicit inherited-pipe camera request. No physical camera has been opened or activated while implementing or unit-testing this source; Linux synthetic receiver class proof is recorded separately.

The proposed capture API takes an inventory-time `ExpectedDevice` proof, the exact `VideoFormat`, a cancellation flag, a once-only readiness callback and a nonblocking encoded-frame callback. The authenticated desktop facade must resolve the user's selected stable source ID to that retained proof. `ExpectedDevice::inspect(path)` reads only device/sysfs metadata: native character rdev and inode, canonical kernel device path and its inode, and bounded USB serial/vendor/product ancestry. Capture compares a fresh snapshot to the selected proof before open and again against the held descriptor before any format changes; it never reconstructs the expected proof at capture time. Reused `/dev/videoN` paths fail closed. There is no default-camera lookup. The facade owns the session epoch, PHV1 sequence/timestamps, independent CameraShare policy and bounded latest-frame output queue.

The initial profile is native single-plane baseline MJPEG, 640 × 480 at nominal 15 frames/s. The backend refuses a different pixel format, resolution, interlaced mode or frame interval returned by negotiation. It does not decode, resize or transcode images. Readiness follows the first structurally validated baseline JPEG with exact dimensions, a baseline SOF0, matching component selectors, a complete sequential SOS, a nonempty entropy scan (including valid byte stuffing/restarts), and an exact final EOI; it does not claim pixel-decoding validation or operating-system permission before capture.

The native handle is restricted to a direct `/dev/videoN` character node opened with O_NOFOLLOW and O_NONBLOCK. The descriptor's character device identity and inode must match the selected path and sysfs node. Native QUERYCAP driver/card/bus identity is checked again on the held descriptor before configuration. V4L2 needs an I/O-capable handle to configure capture queues; the implementation invokes only capture/configuration ioctls, never `write()`. V4L2 requires shared `PROT_READ | PROT_WRITE` mappings even for capture; the Rust code exposes only immutable slices while it owns a dequeued buffer and never writes device memory.

At most four native buffers, each no larger than 2 MiB, plus one owned encoded-frame copy are permitted. A dequeued frame is copied within its validated mapped bounds and requeued before readiness or output callbacks run. Closed/full output queues therefore cannot retain a kernel capture buffer. Owned image copies are zeroed when released. The facade's callbacks must enqueue without waiting for a slow parent pipe.

Frame polling checks cancellation at most every 50 ms. Missing first or subsequent valid frames time out after five seconds. Native configuration ioctls themselves are kernel operations without a general userspace cancellation guarantee: the supervising helper process must enforce its existing startup/shutdown deadline rather than claiming those ioctls have a hard 50 ms bound. An early cancellation returns before opening even a nonexistent source path.

The lifetime guard is installed before changing the negotiated format. Cleanup stops streaming, unmaps and frees native buffers, and attempts to restore the original format and frame interval. Normal capture exit explicitly reports cleanup failures and reads back the original pixel format and frame interval; it cannot report success if restoration was refused. Drop remains a best-effort fallback on constructor failure, disconnection or unwinding, which already fails the capture request. Recoverably corrupted/empty V4L2 frames are requeued and skipped under the same valid-frame deadline; malformed type/index/bounds still abort. Prior application defaults or global camera controls are never selected or changed through an external command.

The initial native ABI is implemented for 64-bit Linux. Local C compilation against the real Linux V4L2 headers confirms the structure sizes, buffer member offsets and ioctl numbers used by the Rust tests. Other pointer widths fail explicitly until their ABI is verified. Pure tests reject node/sysfs inode reuse, rdev/path/serial changes, missing SOS/entropy/EOI, foreign scan selectors, trailing bytes and progressive frames; the real generated colorbar JPEG also passes structural validation. Fake frame backend tests cover exact readiness ordering, progressive/malformed/wrong-size/oversized JPEG rejection, startup timeout, cancellation and closed output. No physical-camera compatibility has been established; reviewed receiver class proof and an explicit native-source test window are still required.

Primary references: [Linux capture API](https://docs.kernel.org/userspace-api/media/v4l/dev-capture.html), [buffer allocation](https://docs.kernel.org/userspace-api/media/v4l/vidioc-reqbufs.html), [stream lifetime](https://docs.kernel.org/userspace-api/media/v4l/vidioc-streamon.html), [frame interval negotiation](https://docs.kernel.org/userspace-api/media/v4l/vidioc-g-parm.html), and [public V4L2 ABI](https://github.com/torvalds/linux/blob/master/include/uapi/linux/videodev2.h).

## Native Windows source checkpoint

The unexported Windows prototype is `windows_video.rs`, with pure `video_pixels.rs`, shared structural `video_jpeg.rs`, and `windows_video_wic.rs`. Real Windows API projections compile for MSVC, including tests; no physical Windows camera has been activated by this implementation yet. Its source is separate from the older microphone-only helper and does not alter that helper's entry points or package manifest.

Metadata discovery uses Media Foundation activation descriptors without calling `ActivateObject`. A capture request must name one exact symbolic link; missing or duplicate matches fail. The adapter requires a nonzero Windows user session, initializes MTA COM/Media Foundation, and activates only the selected object. The authenticated desktop broker remains responsible for SID/logon/session binding and independent CameraShare policy. No system-default camera lookup is used.

The first logical profile remains 640 × 480 nominal 15 frames/s. Matching allows the one-tick rounding of UVC's 100 ns frame interval, rather than treating `10000000/666666` as a different frame rate. It rejects a 30 fps mode. Native MJPEG is preferred. The explicitly bounded fallback supports native NV12/YUY2 at the same profile, converts pixels on the CPU, then uses Microsoft's built-in WIC JPEG encoder. It disables Source Reader converters, hardware transforms and video processing, creates no GPU manager, and performs no resizing. This fallback has metadata/type and pure conversion proof; its actual Windows codec/runtime path still requires a synthetic proof.

YUV conversion respects declared positive row stride, validates both planes/packed bounds, and uses the MF 2D buffer's bounded contiguous copy when available. Reported BT.601/BT.709 and full/limited ranges are supported. Unreported color metadata uses an explicit SD-profile BT.601 limited-range conversion default; this is an application choice, not a claim that the hardware attested its colorimetry. Other reported matrices/ranges fail the mode selection. The software encoder writes into a fixed 2 MiB memory stream that cannot grow; its references are released before reading or freeing that allocation.

Asynchronous sample callbacks copy at most 2 MiB, release native buffer locks before readiness/output, and use a bounded callback queue. Overflow or source mode change stops the request. Readiness requires the first complete baseline JPEG. The polling deadline remains five seconds and cancellation is checked between bounded frame operations; the parent process supervisor must still bound native API/codec calls that the OS does not make interruptible. Successful shutdown explicitly closes the selected media source, with flush/shutdown guards on error paths. No image files, preview window or playback path are created.

Primary references: [Media Foundation capture](https://learn.microsoft.com/en-us/windows/win32/medfound/audio-video-capture-in-media-foundation), [asynchronous Source Reader](https://learn.microsoft.com/en-us/windows/win32/medfound/using-the-source-reader-in-asynchronous-mode), [native image stride](https://learn.microsoft.com/en-us/windows/win32/medfound/image-stride), [WIC encoding](https://learn.microsoft.com/en-us/windows/win32/wic/-wic-creating-encoder), and [fixed-size WIC memory streams](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nf-wincodec-iwicstream-initializefrommemory).
